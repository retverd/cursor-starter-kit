# Унификация правил и документации

План: приведение `cursor-starter-kit` к единой модели правил Cursor, сквозной нумерации префиксов и единого стиля списков.

## Цель

Сделать `cursor-starter-kit` шаблоном репозитория **компонента** с:

- предсказуемой **сквозной нумерацией** правил Cursor (без плейсхолдера `x`);
- явным разделением: смысл документации / контракт публикации / язык / компонент / задача / миграция / процессы;
- шаблонными правилами через `.example`, активными — только то, что нужно каждому проекту.

## Фаза 1. Разделение документации: смысл vs публикация

| Было | Стало |
|------|--------|
| Смешение Antora и смысла в `04-docs-concepts.mdc` | `04-docs-concepts.mdc` — только **смысл** (что писать) |
| Antora-контракт в том же файле или в `1x-antora-docs` | `30-antora-docs.mdc` — **контракт публикации** (где, `xref`, `nav`, `antora.yml`) |

Зафиксировано в:

- обоих правилах (секция «Граница ответственности»);
- `docs/modules/ROOT/pages/architecture/rules.adoc` (подраздел и сигналы размытия).

## Фаза 2. Отказ от `1x-` / `8x-`, сквозные диапазоны

**Решение:** `x` не плейсхолдер цифры, а устаревший маркер класса. Введена единая схема:

| Диапазон | Назначение |
|----------|------------|
| `00`–`09` | Глобальные правила и операции |
| `10`–`19` | Языки |
| `20`–`29` | Типы компонентов |
| `30`–`39` | Цели и задачи |
| `80`–`89` | Временные / миграционные |
| `90`–`99` | Финальные процессы (верификация, ревью) |

**Переименования файлов:**

| Было | Стало |
|------|--------|
| `1x-antora-docs.mdc` | `30-antora-docs.mdc` |
| `10-python-code-review.mdc` | `10-python.mdc` → затем `10-python.mdc.example` |
| `1x-frontend-react.mdc.example` | `20-frontend-react.mdc.example` |
| `1x-backend-api.mdc.example` | `20-backend-api.mdc.example` |
| `1x-python-data.mdc.example` | `30-data-processing.mdc.example` |
| `8x-migration-rule.mdc.example` | `80-migration-rule.mdc.example` |

**Критерий выбора диапазона** при пересечении — в `01-rules-generation.mdc` и `architecture/rules.adoc`: выбирается тот, чьи `globs` **сильнее сужают** контекст (компонент-тип сильнее языка, задача сильнее компонента).

## Фаза 3. Python и ревью

| Было | Стало |
|------|--------|
| `10-python-code-review.mdc` — ревью + язык | `10-python.mdc.example` — **написание** корректного Python-кода |
| Процесс ревью внутри языкового правила | `91-code-review.mdc` — **язык-независимый** процесс ревью (agent-requested через `description`) |

`1x-python-data` **не** сливали с Python: содержимое целиком про data-конвейеры → `30-data-processing.mdc.example` с языко-независимыми `globs` (`data/**`, `pipelines/**`, `etl/**`, `jobs/**`, `dags/**`, `assets/**`).

## Фаза 4. `04-docs-concepts` — общий уровень с `03`

| Изменение | Зачем |
|-----------|--------|
| Остался в `04` (не переносили в `30`) | Общее правило про **любую** пользовательскую документацию, как `03` про репозиторий |
| `globs`: `**/*.{md,adoc,rst}` | Не привязан к Antora |
| Убрана Antora-специфика из текста | Контракт публикации только в `30-antora-docs` |

## Фаза 5. Границы ответственности без дублирования

| Правило | Действие |
|---------|----------|
| `10-python`, `30-data-processing`, `91-code-review` | Убраны локальные «Граница ответственности» |
| `01-rules-generation.mdc` | Добавлен абзац: границы из диапазонов не дублировать в каждом файле; исключение — специфические пары (`04` ↔ `30`) |
| `04-docs-concepts` ↔ `30-antora-docs` | Граница **остаётся** в обоих правилах и в `rules.adoc` |

## Фаза 6. Шаблонность (`.example`)

| Активные в шаблоне | Примеры (`.example`) |
|--------------------|----------------------|
| `00`–`04`, `30-antora-docs`, `90`, `91` | `10-python`, `20-frontend-react`, `20-backend-api`, `30-data-processing`, `80-migration-rule` |

Bootstrap копирует всё; Cursor не подключает `.example` до снятия суффикса. В новом проекте: снять `.example` с нужных, удалить лишние (см. `new-project-bootstrap.adoc`).

## Фаза 7. Единый стиль списков

**Правило пунктуации:**

- пункты 1…n−1 — **`;`**
- последний — **`.`**
- если пункт заканчивается на **`?`** — после `?` **ни `;`, ни `.`**

Проверены и выровнены: `.cursor/rules/**`, `docs/**`, `README.adoc`, `CHANGELOG.md`, `ROADMAP.md`, `.cursor/README.md` (без `.cursor/plans/**`).

## Фаза 8. Документация архитектуры правил

| Файл | Обновления |
|------|------------|
| `architecture/rules.adoc` | Диапазоны, слои, роли файлов, граница `04`/`30`, подраздел **`80-*`** (зачем, отличие от `03`, жизненный цикл) |
| `.cursor/README.md` | Диапазоны, активные vs примеры |
| `README.adoc` | Структура без `10-python` в активных |
| `CHANGELOG.md` | MAJOR: нумерация, переименования, `91-code-review`, `10-python.example` |
| `ROADMAP.md` | Убраны упоминания `1x-*` |

## Что сознательно не входило в коммит

- Реальная сборка Antora / GitLab-рендер (ответственность центрального репо).
- Автоматическая проверка `bash -n` для `bootstrap.sh` в CI.
- Обновление исторических файлов в `.cursor/plans/**` (кроме этого плана).
- Отдельное правило в `01-rules-generation` про пунктуацию списков (пока только практика в текстах).
