# План: правило Python Code Review

## Цель

Создать файл [`C:\Users\retve\VSCode Projects\cursor-starter-kit\.cursor\rules\10-python-code-review.mdc`](C:\Users\retve\VSCode%20Projects\cursor-starter-kit\.cursor\rules\10-python-code-review.mdc), который будет подключаться только при работе с Python-кодом и задавать агенту практические критерии ревью.

## Решение

- Использовать локальное правило, а не глобальное: `alwaysApply: false` и `globs: ["**/*.py"]`.
- Оставить весь пользовательский текст на русском языке, как требуют текущие правила проекта.
- Адаптировать исходный Skill в компактное правило Cursor: не переносить длинные обучающие разделы, таблицы и расширенный шаблон отчёта целиком.
- Обновить проектную документацию:
  - [`C:\Users\retve\VSCode Projects\cursor-starter-kit\.cursor\README.md`](C:\Users\retve\VSCode%20Projects\cursor-starter-kit\.cursor\README.md) — добавить `10-python-code-review.mdc` в перечень правил;
  - [`C:\Users\retve\VSCode Projects\cursor-starter-kit\README.md`](C:\Users\retve\VSCode%20Projects\cursor-starter-kit\README.md) — добавить правило в структуру шаблона;
  - [`C:\Users\retve\VSCode Projects\cursor-starter-kit\CHANGELOG.md`](C:\Users\retve\VSCode%20Projects\cursor-starter-kit\CHANGELOG.md) — зафиксировать добавление нового локального правила.
- Зафиксировать проверяемые пункты ревью:
  - типы и сигнатуры функций;
  - обработка исключений и ресурсов;
  - изменяемые значения по умолчанию;
  - структура, связность и сложность функций;
  - современный синтаксис Python 3.9+/3.10+ там, где он уместен;
  - документация публичных API;
  - применение инструментов `ruff`, `mypy`, `pytest` при наличии конфигурации проекта.
- Добавить короткий формат ответа для ревью: сначала критичные находки, затем вопросы, затем краткая сводка и реально выполненные проверки.

## Границы

- Не менять существующие правила.
- Не добавлять Python-зависимости, конфиги или тестовые файлы.
- Не создавать правило для `pyproject.toml`, потому что задача сформулирована как ревью Python-кода, а в репозитории сейчас нет Python-конфигурации.
- Не дублировать в документации полный чеклист из правила: документация должна объяснять назначение и область применения, а операционные инструкции остаются в `.cursor/rules/10-python-code-review.mdc`.
- Не менять `docs/architecture/overview.md` в рамках этой задачи.

## Критерий успеха

Новый `.mdc` файл существует в `.cursor/rules/`, соответствует формату Cursor rules, не дублирует глобальные правила и будет автоматически применяться к Python-файлам через `globs`. `.cursor/README.md`, `README.md` и `CHANGELOG.md` кратко отражают появление этого правила и не копируют его содержимое.
