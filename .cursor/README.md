# Правила Cursor

Папка `.cursor/rules/` содержит базовые инструкции для агента. Правила должны быть короткими, прикладными и разделёнными по ответственности.

## Диапазоны префиксов

Имена файлов имеют формат `NN-короткое-имя.mdc`. Префикс отражает класс ответственности, а не порядок исполнения.

- `00`–`09` — глобальные правила поведения и операционные процедуры;
- `10`–`19` — правила для конкретных языков программирования;
- `20`–`29` — правила для конкретных типов компонентов;
- `30`–`39` — правила для конкретных целей и задач;
- `80`–`89` — временные и миграционные правила;
- `90`–`99` — финальные процессные правила (верификация, ревью).

## Текущие правила

Активные:

- `00-agent-core.mdc` — базовое поведение агента;
- `01-rules-generation.mdc` — правила развития самой системы правил;
- `02-architecture-principles.mdc` — архитектурные принципы и контрактные риски;
- `03-repo-operations.mdc` — файловые операции, миграции и рискованные изменения;
- `04-docs-concepts.mdc` — смысловое наполнение пользовательской документации;
- `30-antora-docs.mdc` — контракт Antora-компонента и AsciiDoc-ссылок;
- `90-verification.mdc` — обязательная проверка результата;
- `91-code-review.mdc` — язык-независимый процесс ревью, подключается по запросу.

Шаблонные примеры (не подключаются до снятия `.example`):

- `10-python.mdc.example` — пример правила для Python-кода;
- `20-frontend-react.mdc.example` — пример правила для React-фронта;
- `20-backend-api.mdc.example` — пример правила для бэкенд-API;
- `30-data-processing.mdc.example` — пример правила для обработки данных;
- `80-migration-rule.mdc.example` — пример временного миграционного правила.

## Принципы

- `alwaysApply: true` используйте только для устойчивых глобальных правил;
- Технические детали и специфические правила для конкретной технологии должны подключаться через `globs`;
- Процессные правила без привязки к файлам подключаются через `description` (agent requested) или вручную;
- Новые правила добавляются под повторяющиеся типовые ошибки, а не под единичные задачи;
- Документация объясняет контекст; правила задают действия агента;
- Пользовательская документация проекта хранится в AsciiDoc внутри `docs/modules/` и собирается через Antora.
